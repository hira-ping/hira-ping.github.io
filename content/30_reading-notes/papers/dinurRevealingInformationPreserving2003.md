- **n ビットのベクトルとしてモデル化するというのは、かなり強い抽象化なので、これであらゆるデータベースを本当にカバーできるのか？**
	- $n$ビットのベクトルは、考えうる最も単純化されたデータベース（例：特定の病気に感染している=1、していない=0 の1列だけのデータ）。
	- この最も単純な一次元の二値データでさえ、単なるカウントの合計値を返すだけでプライバシーが破綻してしまうのなら、それより複雑なデータベース（例：複数の属性を持つ、連続値を扱う等）でプライバシーを守ることはさらに困難になるということ。
	- これ以上単純化しようがないほど単純な設定でさえプライバシーが崩壊してしまうことを示すのが論文の目的と考えればよい。

>Our main result is a polynomial reconstruction algorithm of data from noisy (perturbed) subset sums.(ABSTRACT)
>
>我々の主な結果は、ノイズが付加された（摂動された）部分集合の和からデータを復元する、多項式時間の再構築アルゴリズムである。(概要)

- 論文の立て付けが、プライバシーの定義を計算量理論・暗号理論の言葉で組み立てるものになっている。
- **攻撃者の計算能力によって結果がガラッと変わる** ことが示されている。
	- →複雑性理論的な発想
	- どれだけの計算資源を攻撃者に許すかによって、必要なノイズの量が変わる。


- **Introductionで明示的に言及されていること**
	- 通常の暗号理論では、計算量的に困難だから安全という考え方が根幹にある(例:離散対数問題が困難だからRSAは安全など)。
	- この論文の non-privacy の定義(Definition 3)も同様の発想で、**計算量的に効率的な(=多項式時間の)アルゴリズムでは復元できない**ことをもって、非公式には守られているとみなす構造になっている。
	- さらに Section 4 の証明では、**Azumaの不等式**を使って攻撃者の確信度が、多項式回のステップでは高い値に到達しにくいということを、ランダムウォークの解析として証明している。これは、暗号理論の識別不可能性の証明でよく使われる技法と同じ発想。

暗号理論とは異なる点もある。暗号理論の安全性は通常、**一方向性関数や離散対数の困難性のような、証明されていない計算量的仮定** に依拠している。

一方この論文の結果(特にSection 3, 4)は、**計算量的な仮定を一切おかず**、統計的な議論(Azumaの不等式や確率の集中現象)だけで証明されている。つまり、攻撃者が本当に $P≠NP$ を破れないから安全という話ではなく、**そもそも情報理論的・統計的に、少ないクエリ数ではデータが集中して求まらない**という、**より無条件に近い保証**になっている。

後の差分プライバシーの枠組みが、計算量的仮定に依存しない、統計的・情報理論的な保証を目指した設計思想につながっている、という意味でも重要なポイント。

> In the query restriction approach, queries are required to obey a special structure, supposedly to prevent the querying adversary from gaining too much information about specific database entries. The limit of this approach is that it allows for a relatively small number of queries.
>
>クエリ制限のアプローチでは、クエリを行う攻撃者が特定のデータベースエントリに関する情報を得すぎるのを防ぐため、クエリに特別な構造に従うことが求められる。このアプローチの限界は、比較的少数のクエリしか許可できないことである。

- SaaSプロダクトでクエリ数を制限するのは、確かに実務上よくある対策
- 後半のBounded adversaryモデルがSaaSに近い
	- 4節で扱っている計算時間T(n)で制限された攻撃者モデルの方が、SaaSの文脈に近い直感を数学的に定式化したものといえる。ここでは摂動を√Tのオーダーに抑えつつプライバシーを保てることを示しており、攻撃者の能力(≒クエリ予算)を制限すれば、必要な摂動を減らせると主張している。
	- → SaaSプロダクトのデータプライバシーを考えるならこっち。
- ユーザーがアウトプットを見て次の一手を考える、というインタラクティブに試せる自由度がなくても、あらかじめ決め打ちされた多項式個のクエリに答える機能さえあれば、再構成は成立してしまう。
- → 試行錯誤できないプロダクトだから安全という推論は、この論文が示した攻撃モデルには直接あてはまらない。
- 安全側に倒せる条件は以下の場合
	- 本当に1回(あるいは定数回)しか統計を返さない; かつ
	- 各回答自体が単体で個人を特定できるほど精緻ではない
		- これなら √n オーダーの摂動を持ち出す必要はない。
			- ただし、現実のプロダクトでは、例えば、ユーザーは3回しか触れないとしても、そのプロダクトが多数のユーザーに対して延べで大量の統計を返している、あるいは1回のレスポンスに大量の集計値(ダッシュボードの多数の指標など)が同時に含まれている、というケースがあり、その場合は累計のクエリ数で見ると全然少数ではなくなってしまう。
- 実例:米国センサスのケース
	- 差分プライバシーが実務で本格採用された最大の動機の一つ。米国国勢調査局は2020年国勢調査で、ユーザーが対話的にクエリを投げられるシステムではなく、一度きりの静的な統計表の公開にDP(差分プライバシー)を導入した。理由は、公開される表の数・粒度(郡・地区・年齢層別など多数のクロス集計)が十分豊富だと、たとえ、利用者が試行錯誤できない一方向の公開であっても、複数の表を組み合わせるだけで個人の再構成が可能だと実証されたから。この論文が理論的に予言した再構成攻撃が実務で現実化した例。

**元データをある程度ならした統計データを作ってそれを公開したとき、それから元データを推測できるか？というテーマの考え方。**

論文のモデル（攻撃者が逐次的にクエリを投げ、その都度応答を受け取る対話型の設定）に対して、ならした統計データを作って公開する非対話型（あるいは一括公開）と呼ばれる設定の場合の考察。あらかじめ決まった統計量の集合を一度にまとめて公開するイメージ。

この違いは、Dinur-Nissimの攻撃アルゴリズムにとってほとんど障害にならない。

> Query phase: $t$ 個のクエリ $q1,…, \ldots, q_t $をランダムに(非適応的に)選ぶ

つまりこの攻撃自体が、最初からクエリを適応的に選ぶ必要がない設計になっている。

→「公開された $m$ 個の統計量」を、そのまま「あらかじめランダムに選ばれた $m$ 個のクエリへの応答」とみなせば、そのままこの攻撃が適用できることになる。

→ **米国センサスのケース**

この問題を考える上で重要なのは、以下のパラメーター

1. **公開する統計量の数 $m$**(元データのサイズ $n$ に対してどのくらいか)
2. **平滑化(ノイズ・丸め・粗視化)の強さ $\mathcal{E}$**

Theorem 3 の結果を当てはめると、

$m≳n(\log⁡{n})^2$ かつ $\mathcal{E}= \omicron(\sqrt{n})$

の両方が満たされる場合、公開された統計データから元データのほぼ全体($1-\varepsilon$ 以上)を復元できてしまうことになる。

つまり、直感的には、

- 公開する統計の本数がデータベースの人数と同程度以上ある
- かつ、それぞれの統計に加えたノイズ・丸めの誤差が $\sqrt{n}$未満

という2条件がそろうと、たくさんの断面図を集めれば元の立体が復元できてしまうように、元データを復元できてしまう。

統計化の具体的な方法によって、実質的に何がクエリ集合 $\{q_j\}$ になるかが変わってくる。

- **単純な集計表(クロス集計表・マージナル表)の公開**: 
	- 例えば、年齢層×性別×疾患の有無ごとの人数を公開する場合、これは実質的に多数の部分和クエリを一括で答えているのと同じ。カテゴリの粒度が細かいほど、また公開する断面の組み合わせが多いほど、$m$ が大きくなり、攻撃が成立しやすくなる。
- **ラウンディング(丸め)**
	- 例えば、10人単位に丸めて公開のような処理は、Definition 2 の摂動 $\mathcal{E}$ に対応する。丸め幅が $\sqrt{n}$ より十分小さければ、攻撃者にとって障害にならない。
- **k-匿名化のような粗視化**
	- グループの粒度を粗くする方法は、グループごとの合計という形の部分和クエリを晒しているのと同じ。
